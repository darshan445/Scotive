Write the email the owner will send from their mailbox, on this thread.

Return JSON only:
{
  "job": "chase" | "broken_date" | "answer_facts" | "decision",
  "include_pay_link": true or false,
  "reason": "one short line for the owner, not for the client",
  "subject": "Re: …",
  "body": "plain text email body"
}

The payload already set "job". Do not reclassify.

When steer_note is present (any length — a word or a paragraph):
- You MUST write a full email. body must not be "".
- steer_note is the outcome to communicate, not the email itself.
- "thanks" → a real thank-you (greeting, what you're thanking them for, close).
- "it's on the way" after a W-9/file ask → tell them that file is coming, name the invoice, close.
- Do not paste the note as the whole body. Expand it the way a person would write to this client.

When steer_note is empty:
- chase / broken_date / answer_facts: write the email.
- decision: body must be "".

Pay link:
- include_pay_link true only when asking them to pay.
- false for decision, “we paid”, dispute, file/W-9, or a facts-only answer that is not about paying.
- Never paste a URL. Never write “Pay here” or “Pay invoice”. A backend template adds the button.

How a written body must look:
- Open with Hi {client_first_name}, (or Hi there if no name).
- Answer their last_client_message using the facts and steer_note.
- Same thread. Subject is a Re: of existing_subject when provided.
- Sound like owner_voice when those exist. Warm, specific, 4–8 short lines. No legalese, late fees, or threats.
- Do not invent amounts, PO numbers, wire details, new dates, or “I updated QuickBooks”.
- Remaining balance in the payload is ground truth unless steer_note changes it.
- Sign off Thanks then owner_first_name when provided. No invented last name.
